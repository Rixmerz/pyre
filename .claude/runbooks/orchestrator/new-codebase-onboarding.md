## Steps

1. Read `.claude/notions/project-tree.md`. This is auto-generated by `jig init`. If missing, run `jig resync` (CLI, outside session).
2. From the tree extract: dominant languages, marker files, presence of `.sca/`, `.dcc/`, `.livespec/` directories.
3. Run `/context-swarm` to spawn `dcc-specialist` + `livespec-specialist` in parallel. (Add `sca-specialist` if registered.)
4. Wait for both/all to write notions under `.claude/notions/`.
5. Read each notion. Synthesize executive summary for user.

## Tools (specific calls)

```
# Read tree first
Read(".claude/notions/project-tree.md")

# Parallel swarm (single assistant message, multiple tool_use blocks)
Task(subagent_type="livespec-specialist", prompt="<see /context-swarm command>", run_in_background=true)
Task(subagent_type="dcc-specialist",      prompt="<see /context-swarm command>", run_in_background=true)
```

## Response format

```
**Tech**: <languages + frameworks from tree+livespec>
**Size**: <files / LoC from dcc-snapshot>
**Architecture**: <top-3 modules by PageRank>
**Risk hotspots**: <top critical/high smells from dcc-snapshot>
**Where to look first**: <suggested file paths>

Notion files written:
- .claude/notions/project-tree.md
- .claude/notions/livespec-overview.md
- .claude/notions/dcc-snapshot.md
```

## Failure modes

- Specialist times out → reduce scope in retry (e.g. `cube_index_directory(path=<subdir>)`).
- Notion file empty → specialist hit gate; verify `delegation_gate.py` detects subagent (look for `/subagents/` in transcript_path).
- User pushes back on missing detail → spawn `codebase-analyst` with targeted question, not full re-scan.
